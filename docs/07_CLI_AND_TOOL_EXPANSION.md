# EvidenceCoder 0.3.0 CLI 与工具扩展实施记录

> 状态：用户于 2026-08-30 审批通过，功能已实现并完成自动测试与相似性复核。

## 1. 实施范围

本次只实现审查通过的高价值、低到中风险能力：

- 使用 Rich 提供彩色面板、模型等待状态、紧凑工具结果和历史/status 表格。
- 写入审批前显示有界 unified diff；预览不修改文件，实际操作仍经过 Guard 和工具校验。
- 新增 `read_many`，一次读取最多 10 个已知文件，总返回字符受限。
- 新增只读 `git_status` 与 `git_diff`；要求工作区是仓库根目录，不提供 add、commit、reset 或 push。
- 汇总逻辑模型调用数、工具调用数、任务耗时和网关实际返回的 token 用量。
- 新增 `/retry`，以新 RunBook 重试上一条指令；旧操作编号仍不可作为新任务证据。
- 新增 `/export [path]`，在工作区内原子生成 Markdown 对话报告。

未实现删除工具、撤销、全屏 TUI、流式 tool call、多 Agent、MCP、插件和自动 Git 写操作。

## 2. 控制流边界

Rich 没有进入 Agent 决策。`Engine` 仍然唯一拥有 COMPOSE—ASK—CHECK—AUTHORIZE—ACT—
ASSESS 循环，只通过单向 `AgentEvent` 回调报告“模型开始/结束、自然语言、工具结果”。显示层
不能追加 RunBook、调用工具或决定终止，因此这不是事件总线或第二套控制器。

三个新工具仍在固定 `Toolbox` 中声明 schema 并由同一分派函数执行，没有动态 registry、插件
发现或外部扩展协议。Git 工具先确认当前工作区就是仓库根目录，路径参数解析后必须仍在工作区。

## 3. 设计理由

- `read_many` 减少读取多个已知文件所需的模型往返，但通过文件数和总输出上限控制上下文。
- Git 只读观察帮助模型区分用户已有修改和本次修改；其他 Git 命令仍需经过 Shell 审批，
  其中 push、hard reset、forced clean 等危险操作继续硬拒绝。
- diff 预览服务于用户授权，不替代 `replace_text` 的精确匹配或 `write_text` 的原子写入。
- token 只汇总网关报告的 usage；未报告时明确显示 unknown，不把字符估算冒充计费数据。
- `/retry` 新建任务凭证域，保持 EvidenceCoder“当前声明只能由当前运行证明”的核心约束。

## 4. 验收结果

- 42 项测试通过；1 项目录符号链接测试因本机不支持而跳过。
- 真实本地 HTTP 端到端测试覆盖 `.env`、CLI、写入、命令和凭证提交。
- 新增测试覆盖 Rich 结果、diff 预览、批量读取上限、Git 路径边界、token 汇总、重试和导出。
- 18 个自研运行时源码文件再次对照 5701 个参考源码文件扫描，所有候选列表为空。

## 5. 0.3.1 对话恢复选择器

用户追加审查通过后，`/resume` 无参数形式改为列出当前工作区最近 20 个有效对话，展示
更新时间、任务数、状态和最后一条指令，并通过序号选择。空输入或 `q` 取消；原有
`/resume latest` 与 `/resume <id>` 保持兼容。列表只接受工作区指纹匹配且格式有效的记录，
损坏文件会跳过。该补丁完成后共 45 项测试通过，七仓库复扫仍为零候选。
